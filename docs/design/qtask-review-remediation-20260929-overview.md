# PLAN-021 复查修复设计

- 日期：2026-09-29
- 状态：实施依据
- 依据：PLAN-020 后的运行时复查（停机领取、外存回收、搜索游标、稀疏筛选、测试基线）。

## 1. Worker 停机边界

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 停机后继续执行已领取的新任务 | 改动少 | 停机语义不清，且心跳可能提前退出 |
| 仅在领取后检查停止信号 | 不再运行 handler | 已消耗的 attempt 若不回滚会导致首次执行前耗尽预算 |
| 停机持续续租，并原子退回尚未进入 handler 的 claim | 停机与重试预算一致，覆盖阻塞领取及线程池等待 | 需要一条有所有权检查的 Redis 转换 |

采用第三种。`stop()` 在主循环退出和线程池 drain 前始终保持心跳。handler 准入与停止信号共用短临界区，确定谁先发生；启动前已收到的停止信号不被 `run()` 清除。已开始 attempt、尚未准入 handler 的 claim 由 Lua 核对原消息和 attempt 后放回 ready、恢复 attempt 与 deadline 索引、释放并发租约。临界区只保护准入，不等待 handler 运行，停止请求可及时通知正在运行的任务。若消息已被其他转换接管，不再覆盖其状态。

## 2. 外存待入队回收

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 延长临时 claim TTL | 实施简单 | 文件删除后进程退出仍有时间到期窗口 |
| 删除文件前原子移除 pending | 入队立即拒绝失效引用 | 文件删除失败会留下无回收记录的孤儿 |
| 原子把到期 pending 转入持久 GC 日志，再删文件 | 入队拒绝且删除失败可重试 | 回收最多延后一轮轮询 |

采用第三种。pending→GC 是 Redis 原子转换。删除文件和移除 GC 日志允许重复；进程在任一步骤退出，下一轮继续。手动删除同样先转移 pending，避免文件已删除但 Redis 仍允许入队。保留旧 claim 检查以兼容滚动升级期间的旧服务端。

## 3. 搜索与分页接口

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 每页重新发现全部队列 | 无新状态 | 新队列会改变游标指纹，旧页无法继续 |
| 游标保存队列快照 | 翻页稳定，可复现原查询范围 | 游标体积随队列数增长 |
| Redis 保存服务端游标 | URL 短 | 引入过期、共享状态和额外读写 |

采用压缩的自包含队列快照。`search_tasks_page(queues=None)` 表示“查询开始时的全部队列”；继续翻页沿用快照，不重新发现。显式队列列表仍校验调用方是否改变筛选。游标保持不可信输入，检查结构、长度、过滤条件和偏移。

稀疏筛选每次 HTTP 请求只扫描至多 5000 条并返回 `next_cursor`、`scan_limited`。旧 `list_tasks()` 列表接口保留便捷用途，但达到扫描预算时显式报错并提示调用分页接口，避免一次请求无界扫描。

## 4. 三轮查漏补缺

1. **正常路径**：停机前已运行的 handler 持续续租直至退出；停机后领取的消息可继续被其他 Worker 处理。外存 live/DLQ 保留与终态清理语义不变。
2. **并发与故障**：退回 claim 必须验证原始消息、当前 attempt 和非终态；定时和手动删除都先移交 pending 再删文件；进程崩溃后 GC 日志仍在；新增队列不影响既有游标。
3. **兼容与资源**：旧游标在队列集未变时仍可解析；旧外存 claim 仍被入队拒绝；稀疏查询达到扫描预算会明确续页或报错；既有测试按新指标回填和鉴权契约更新。
