# PLAN-022 执行结果：CLI 与 Dashboard 运维场景优化

## 评审与实施

1. 按值班巡检、无人消费、纯延迟等待、DLQ 处置、跨队列排查、Redis 故障、手工投递和远程访问等真实场景审查现有入口。设计文档比较了 CLI 巡检、Worker 启动、远程 Dashboard、进度口径和任务搜索的方案，并完成正常、故障、边界三轮查漏补缺。
2. `qtask status` 新增全局 namespace 筛选、`--problems-only`、完整状态 `--json`；默认表格显示 retry_wait、过期、在线/失联 Worker。`watch` 补状态并限制最短间隔；`worker` 只接收必填业务模块，移除无效参数；CLI 绑定远程地址且没有认证时要求显式 `--allow-unauthenticated`。
3. Dashboard 全局任务查询接入统一 API，支持 action、发布时间和完成时间筛选；筛选变化重置游标并避免旧响应覆盖新结果。任务详情修正过期与重试等待派生状态、真实时间线和过期任务专用重放路径。过期重放拒绝已过去的新截止时间，旧任务保持不变。
4. 总览和队列页把累计数据与浏览器观测值分开表达：不再把打开不足一小时的增量写成“完成/1h”，不显示无法推断的批次百分比；速率至少观测 30 秒，疑似停滞需 ready 积压、在线 Worker 且连续 2 分钟无完成；纯延迟队列显示等待调度。新增“ready 有任务但无 Worker”告警。
5. 顶栏刷新现可立即请求，操作后同步刷新全局数据；健康检查失败时显示连接异常、上次成功更新时间和不可判定空态。手工投递移入次级操作，明确真实业务副作用，验证输入并保留去重拒绝反馈；修正 Worker 示例、教程与 README。

## 使用边界

- 观测完成量、速率和 ETA 只在当前页面采样期间有效；真正的批次完成率仍需要调度器提供轮次与期望数量。全局搜索仍受已有扫描预算约束。
- 告警确认仍保存在浏览器本地；多人共享确认和精确滚动窗口失败率需要额外服务端模型。
- 远程无认证保护只覆盖 `qtask dashboard` 启动命令；直接运行 uvicorn 时需自行配置认证。`qtask worker` 的旧无效选项现在会明确报参数错误。
