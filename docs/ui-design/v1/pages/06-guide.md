# 页面设计：教程 `/guide`

- 服务场景：S5 新管理员上手 `[新增]` —— 第一次接触这个后台的人，能自己看懂概念、知道去哪操作
- 频率：低频但每次入职/交接必看；信息优先级：P1 = 概念解释（说人话）；P2 = 状态流转图；P3 = 操作速查表

## 设计原则

1. **说人话**：每个概念先用一句大白话定义，再给术语对照；禁止只抄 README 术语。
2. **问答式组织**：按"新人会问什么"组织（任务和队列什么关系？这堆状态什么意思？DLQ 涨了怎么办？），不按代码结构组织。
3. **可视优先**：状态流转用徽章+箭头图，不用大段文字。
4. **前后端事实一致**：教程内容与 README/`QueueAdmin` 语义对齐（如 `max_retry=3` = 总共 3 次，不是再试 3 次），避免教错。

## 组件

- `<GuidePage>`：`<TocChips>`（锚点跳转）+ `<GuideSection>`（标题带 `#` 锚点、正文、`<ExampleBox>` 示例框、`<StateFlow>` 徽章流程图、`<OpsTable>` 速查表）。
- 复用 `<Badge>`/`<StateBadge>` 表达状态，保证教程里的状态颜色与全站一致（教程本身也是状态色的记忆锚点）。

## 主行动点

无表单操作；TOC chips 是主要导航。与告警页"规则说明"一样，教程也承担"解释为什么"的职责。

## 状态

- 默认：全部展开的单页长文（长度约 4~6 屏）。
- 极端：不需要分页；若章节增加到 10+，TOC 收进左侧 sticky 导航 `[假设，后续版本]`。
- 维护约定：教程是文档（`pages/06-guide.md` §3），原型中的文案只是初稿；实现时文案单独放常量文件，改文案不改组件。

## 内容清单（说人话初稿，正式文案随实现评审）

1. **30 秒总览**：程序→队列→Worker→完成/重试/DLQ 的全链路一句话 + 流程框。
2. **任务和队列的关系**：队列=一类活的流水线；任务=其中一件具体的事；namespace=项目分组前缀；对应到后台就是"队列页看流水线、任务表格看每件事"。
3. **任务的一生（状态）**：ready/delay/retry_wait=还没干；processing=正在干；completed/failed/dlq/skipped/cancelled/deadline_missed=干完了（好坏/原因）；各状态配徽章图。
4. **关键数字怎么读**：attempt（max_retry=3 是总共 3 次）、剩余、速率（前端采样，冷启动 ~10s 显示 —）、ETA、停滞判定。
5. **去重**：logical_key 是"这件事的身份"，在途不重投；时间桶让跨期天然是新任务。
6. **Worker 与心跳**：心跳=报平安；失联=任务变孤儿可被恢复；崩溃不丢任务但可能重跑→落库要幂等。
7. **日常操作怎么做**：场景→页面→动作速查表（DLQ 重放/失联恢复/过期重放/清空删除/投递测试）。
8. **后台各页是干嘛的**：一句话导览。
