# PLAN-020：全代码设计评审问题修复

- 日期：2026-09-29
- 范围：2026-09-29 全代码设计评审列出的九项问题及实施时发现的直接关联缺陷。
- 设计依据：`docs/design/qtask-remediation-20260929-overview.md`。
- 目标：恢复 Worker 心跳与并发租约的可靠性，闭合 RemoteStorage 的安全和生命周期，修正管理操作、查询、指标与公开启动接口。

## 一、约束与验收口径

1. 保持 V2 的 at-least-once、终态不可重开、DLQ 可重放、live identity 不提前过期语义。
2. 心跳和租约续期不受归档、诊断、告警、外存请求等慢操作阻塞；线程池中待执行的 claim 也持续续租。
3. RemoteStorage 默认只监听本机；远程请求需鉴权；上传体积有明确上限。Dashboard 不回传 Redis 凭据。
4. 外存对象在任务仍可执行或可重放时可读取；终态保留结束后可自动回收；共享对象不得因单个任务结束被误删。
5. 删除和清空操作对活跃 processing 有明确、可审计的行为；Dashboard 确认内容与实际范围一致。
6. 队列总览不再按每条队列读取固定 2000 条历史和大批任务消息；多队列搜索不因队列顺序或先截断而漏匹配。
7. 总览剩余数不重复统计 retry_wait；速率以单调完成计数计算。`start_dashboard()` 在当前单包结构下可启动。

## 二、实施顺序

### A. Worker 与状态边界

1. 将 heartbeat/lease 续期移至独立轻量线程；维护线程只执行低频任务。
2. claim 一旦进入本进程的 processing 就纳入续租集合，覆盖线程池待执行阶段。
3. 复查停机 drain、信号、executor 提交失败与心跳清理顺序。

### B. RemoteStorage 与管理安全

1. 按设计文档确定对象独占或共享引用方案，明确 enqueue、replay、终态、DLQ、管理删除、异常网络窗口的保留规则。
2. 完成服务端鉴权、默认监听地址、上传上限与客户端认证配置。
3. 建立可重试的外存终态回收路径，并覆盖旧对象兼容。
4. 管理删除与清空以原子状态转换处理；活跃 handler 的风险在接口中显式表达并在 UI 准确告知。
5. 隐去健康接口和启动日志中的 Redis URL 凭据。

### C. 查询、指标与公开接口

1. 改造 QueueAdmin 队列发现与总览统计，复用状态脚本维护的计数，新增活跃 deadline 索引与 retry_wait gauge，保留旧消息兼容回填。
2. 修复跨队列任务搜索与状态筛选：先匹配、后分页，并给出稳定排序与扫描边界。
3. 修复总览剩余数和速率来源，检查告警阈值口径。
4. 修复 `start_dashboard()` 模块路径及可选依赖错误提示。

### D. 复查与交付

1. 对正常执行、长任务、队列积压、外存重放、删除、归档、搜索、Dashboard 启动做针对性验证。
2. 全量复查变更与设计约束，修正发现的问题。
3. 更新 README、设计文档与示例；生成 `docs/dev/PLAN-020-review-remediation-OUTCOME.md`。
4. 在 `docs/dev/INDEX.md` 追加计划和结果对应摘要；按项目规则以中文提交并立即推送。
