# 页面设计：总览（Overview）

- 路由：`/` · 服务场景：S1 巡检 · 频率：高
- 信息优先级：P1 = 全局健康摘要 + 异常队列；P2 = 告警摘要；P3 = 正常队列明细

## 布局

```
┌──────────────────────────────────────────────────────────────┐
│ KPI 行:  队列 12   DLQ 3 ⚠   失联 Worker 1 ⚠   Redis 内存 62%  │  ← P1
├──────────────────────────────────────────────────────────────┤
│ 告警摘要（最新 5 条，每条: 严重度点 · 规则 · 队列 · 时间 · 定位）│  ← P2
├──────────────────────────────────────────────────────────────┤
│ 队列健康矩阵（按 namespace 分组）                              │
│ ┌ stockev ────────────────────────────────────────────────┐  │
│ │ day-kline:fetch   ready 120  dlq 0  fail 2%   [正常]     │  │
│ │ quote:5min        ready 8    dlq 1  fail 1%   [DLQ ⚠]   │  │  ← P1 异常项高亮
│ │ news:discover     ready 0    dlq 0  fail 0%   [空闲]     │  │
│ └──────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

## 组件

- `<HealthSummaryCard>`：4 个 KPI（队列总数、DLQ 总量、失联 Worker 数、Redis 内存百分比）。数值非 0 异常时用语义色，正常用 primary 灰蓝。点击 KPI 下钻（DLQ → 告警中心已过滤视图）。
- `<AlertDigest>`：复用 `<AlertItem compact>`，只读 + 定位；尾部"查看全部 →"。
- `<QueueHealthMatrix>`：每行一个队列，列 = ready / processing / retry_wait / dlq / 失败率 / 健康徽章。行点击 → 队列详情。排序：异常优先（danger > warning > 正常 > 空闲），同组内按 DLQ 降序。

## 主行动点

无强 CTA（状态确认型页面）。唯一明显可点元素组是矩阵行与告警定位。

## 状态

- 首次加载：KPI 与矩阵显示骨架屏（避免旧版"先空白后跳数据"）。
- Redis 不可达：页面顶部红色错误条 "Redis 连接失败: …" + 重试；矩阵置灰。
- 无队列：矩阵区显示引导卡"还没有队列。用 `qtask push` 或在队列页投递第一条任务"。
