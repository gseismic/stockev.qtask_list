# 页面设计：队列列表 + 队列详情

## 队列列表 `/queues`

- 服务场景：S1、S2 · 频率：高
- P1 = 异常队列一眼可见；P2 = 队列级控制；P3 = 删除队列

### 布局

```
┌────────────────────────────────────────────────────────────────┐
│ 筛选: [namespace ▾]  ( )全部 (•)进行中 ( )仅异常   🔍 搜索  共 N 个│
├────────────────────────────────────────────────────────────────┤
│ ┌──────────────────────┐ ┌──────────────────────┐              │
│ │ stockev:quote:5min ⚠ │ │ bf:kline:2023        │              │
│ │ ▓▓▓░░░░░ 73%         │ │ ▓░░░░░░░ 20%         │              │
│ │ 剩余266 完成/1h 720   │ │ 剩余8638 完成/1h 2200 │              │
│ │ 速率12/min ETA约22min │ │ 速率37/min ETA约3.9h  │              │
│ │ [详情] [操作▾]        │ │ [详情] [操作▾]        │              │
│ └──────────────────────┘ └──────────────────────┘              │
└────────────────────────────────────────────────────────────────┘
```

- `<QueueCard>`：名称、健康徽章、`<ProgressBar>` 三段式进度条、
  剩余 / 完成·1h / 速率 / ETA / dlq 摘要行（口径同总览，见 pages/01-overview.md）。
- `[操作▾]`（P2 收纳菜单）：投递测试任务 / drain 旧 retry / 重放全部 DLQ / 恢复 stale processing / 清空队列 / 删除队列。危险项红色 + 二次确认。
- 筛选：namespace 下拉 + 全部/进行中/仅异常 三态 + 名称搜索（与总览矩阵口径一致）。
- 大规模（100+ 卡片）：与总览一致按 namespace 分节；本页定位是"管理与入口"，盯盘优先用总览。

### 状态

- 空：引导投递。加载：骨架卡片 ×6。错误：横幅 + 重试。
- 极端：队列多时卡片网格分 namespace 分节。

## 队列详情 `/queues/:ns:name`

- 服务场景：S2、S3 · 频率：高
- P1 = 任务表格及其筛选；P2 = 队列级控制（收纳）；P3 = 诊断与危险区

### 布局

```
┌──────────────────────────────────────────────────────────────┐
│ stockev:quote:5min          ready 8 · processing 2 · dlq 1 ⚠ │
│ [投递测试任务]  [操作 ▾]        [诊断]  [⚠ 危险操作 ▾]         │  ← P2/P3
├──────────────────────────────────────────────────────────────┤
│ Tabs: all | ready | processing | retry | retry_wait | delay  │
│       | dlq(1) | completed | failed | skipped | cancelled    │
│       | deadline_missed | history                             │  ← 状态完整枚举
├──────────────────────────────────────────────────────────────┤
│ 筛选: 🔍 task_id/action/payload   [action ▾] [时间范围] [刷新]│
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ task_id     action        attempt 状态    发布时间  完成  │ │
│ │ 8f3a…c2     fetch_quote   2      ⚠retry_wait 10:00  —   │ │
│ │ 91bd…7e     fetch_quote   1      ✓completed  09:55  09:55│ │  ← 点击行开抽屉
│ └──────────────────────────────────────────────────────────┘ │
│ ‹ 1 2 3 … ›  共 137 条                                        │
└──────────────────────────────────────────────────────────────┘
```

### 组件

- `<QueueHeader>`：名称 + stats 徽章行。主 CTA 唯一 = `投递测试任务`（对应 `push_task`）。其余操作收进 `[操作▾]`：move_retry / requeue_dlq / recover / clean_history。诊断按钮打开 `<QueueDiagnostics>` 侧板。危险区（清空/删除）独立红色下拉 + 确认。
- `<StateTabs>`：完整 `QueueState` 枚举，带计数的 tab 显示数字徽章（dlq(1)）。从告警跳入时 URL 带 `?state=dlq` 直接激活对应 tab。
- `<TaskFilterBar>`：搜索（task_id/action/payload，防抖 300ms）、action 下拉（从当前数据聚合）、时间范围（created/completed）、自动刷新开关。
- `<TaskTable>`：列 = task_id（短显示 + 复制）、action、attempt、状态徽章、发布时间、完成时间。分页 50/页。

### 状态

- 选中状态 0 条：`"dlq 队列是空的——任务重试耗尽才会进入这里。"` + "查看 all" 链接。
- 表格加载：骨架行 ×10；错误：表格区错误 + 重试。
- 极端：payload 超长在表格中截断为 `fetch_quote({symbol: "AAPL",…})`，完整内容在抽屉。
